# Warren API contract

This is the contract every component implements against: the daemon's **Sandbox API**, the per-instance **Agent API** served by the gateway inside each instance, and the **edge** rules that join them. Changes here are breaking changes.

## Planes and hosts

| Plane | Host | Auth | Served by |
|---|---|---|---|
| Sandbox API | `api.<base>` and `<base>` with path `/v1/...` | `Authorization: Bearer sk_live_...` (also accepts `X-Warren-Key`) | `warren-api` |
| Instance URLs | `<id>.<base>` (default port) and `<id>-<port>.<base>` (any port) | `X-Warren-Key: sk_live_...`, or a signed URL (`?warren_token=`) which sets the `warren_session` cookie, or `Authorization: Bearer` | `warren-edge` proxying to the instance |
| Dashboard | `<base>` root | browser, stores an API key locally | `warren-dashboard` |

`<base>` defaults to `warren.localhost` and URLs carry the public port, so locally: `http://api.warren.localhost:7337/v1/...`, `http://ab12cd34ef.warren.localhost:7337/`, `http://ab12cd34ef-7681.warren.localhost:7337/`.

Unauthenticated instance requests get `401 invalid_api_key`. A request to a sleeping instance is held while the instance wakes, then forwarded. A request to a stopped instance gets `409 conflict`. A port nothing listens on gets `502 bad_gateway` (a plain-text body is fine; the URL always routes).

CORS: only trusted origins are granted. On an instance host the trusted origins are the dashboard (`<scheme>://<base>[:port]`, the root host) and the instance's own origins for the requested host (`instance_url(id)`, plus `preview_url(id, port)` on a port host). The edge answers `OPTIONS` on instance hosts with `204`; when the request `Origin` is trusted it adds `Access-Control-Allow-Origin: <request Origin>`, `Access-Control-Allow-Headers: X-Warren-Key, Content-Type, Authorization` (plus any requested headers), `Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS`, `Access-Control-Allow-Credentials: true`, and adds `Access-Control-Allow-Origin`/`-Credentials` to proxied responses and edge errors. Any other `Origin` gets no `Access-Control-Allow-Origin` at all (only `Vary: Origin`). The API host trusts the dashboard origin only.

## Conventions

- Instance ids: 10 lowercase alphanumerics starting with a letter (`ab12cd34ef`); also the DNS label.
- Other ids: 32 hex characters. Workspace ids: `ws_` + 20 lowercase alphanumerics. API keys: `sk_live_` + 40 base62 characters; only the SHA-256 is stored.
- Timestamps: unix seconds on the Sandbox API; the Agent API uses unix milliseconds.
- Lists: `{ "data": [...] }`, newest first.
- Errors: `{ "error": { "code": "...", "message": "...", "details": {...} } }`. Codes: `invalid_request` 400, `not_supported` 400, `invalid_api_key` 401, `forbidden` 403, `not_found` 404, `conflict` 409, `instance_limit_reached` 409, `host_capacity_reached` 409, `try_again` 503, `timeout` 504, `internal` 500.
- Instance `status`: `provisioning | running | stopping | stopped | starting | restarting | updating | sleeping | waking | failed | deleting | deleted`.
- Unknown JSON fields are rejected with `invalid_request`.

## The instance object

```json
{
  "id": "ab12cd34ef", "workspace_id": "ws_...", "name": "Production agent",
  "template": "warren-agent", "template_name": "warren-agent", "template_revision": 1,
  "image_ref": "warren/agent:dev", "type": "default", "status": "running", "status_reason": "",
  "resources": { "cpu": 2, "memory": 4, "disk": 4 }, "region": "local",
  "metadata": { "plan": "pro" }, "env": { "APP_ENV": "production" },
  "network": "allow-all", "auto_sleep": true, "idle_timeout_seconds": 900,
  "url": "http://ab12cd34ef.warren.localhost:7337", "default_port": 3737, "mount_path": "/home/agent", "agent_api": true,
  "parent_id": "", "created_at": 1763000000, "updated_at": 1763000100, "started_at": 1763000050,
  "stopped_at": 0, "slept_at": 0, "last_activity_at": 1763000100,
  "runtime": "docker", "disk_used_bytes": 123456
}
```

`url` is derived from the base domain; `runtime` is `docker`, `firecracker` or `lume`. `published_ports` appears only on hosts that cannot route to the instance's network (macOS hosts with Docker Desktop or the smolvm engine, `--docker-publish-ports`): a map of instance port to the `127.0.0.1` port the daemon proxies through, for example `{"3737": 54321, "7681": 54322}`; preview URLs for ports outside the map answer `400 not_supported` there. `type` is `default` (gVisor container), `vm` (Firecracker microVM) or `mac` (macOS VM through Lume on an Apple silicon host; see [macos.md](macos.md)).

## Sandbox API (`/v1`)

### Health, version, signup
- `GET /v1/health` -> `{ "healthy": true, "version": "...", "runtimes": ["docker"], "dev_mode": false, "time": 1763000000 }`. No auth. `runtimes` lists the runtimes that came up at startup: `docker` (type `default`), `firecracker` (type `vm`), `lume` (type `mac`).
- `GET /v1/version` -> `{ "version": "..." }`. No auth.
- `POST /v1/signup` body `{ "name"?: string }` -> `201 { "workspace": { "id": "ws_...", "name": "...", "created_at": ... }, "api_key": "sk_live_...", "key_id": "..." }`. No auth. `404 not_found` when the daemon runs with `--signup-enabled false` (`WARREN_SIGNUP_ENABLED`). Limited to 10 signups per hour per client IP, `429 try_again` beyond that; in dev mode loopback clients are exempt.

### Workspace and keys
- `GET /v1/workspace` -> workspace object plus `{ "awake_limit": 3, "awake_count": 1 }`. `awake_limit` is the daemon's `--max-awake-instances` value, or `null` when the daemon has no limit; `awake_count` is the number of this workspace's instances in an awake state right now.
- `GET /v1/api-keys` -> list of keys (no hashes). `POST /v1/api-keys` body `{ "name"?: string, "expires_at"?: int }` -> `201 { "key": {...}, "api_key": "sk_live_..." }` (plaintext shown once). `DELETE /v1/api-keys/{id}` -> `{ "id": "...", "deleted": true }`. Deleting the key used for the request is allowed.

### Awake quota
The daemon may cap the number of instances a workspace keeps awake at once: `--max-awake-instances N` (`WARREN_MAX_AWAKE_INSTANCES`); unset means unlimited. Awake means `provisioning`, `running`, `starting`, `restarting`, `updating`, `stopping` or `waking`; sleeping and stopped instances never count. The cap is enforced on create, start, wake (a request to an instance URL, an exec, a cron firing) and fork, which answer `409 instance_limit_reached` with `details: { "limit": N, "awake": n }` when the workspace is at the limit.

### Host capacity
A host may also be unable to run another instance of a type regardless of the workspace: a Mac runs at most two macOS guests at once. Then create, start, wake and fork answer `409 host_capacity_reached` with `details: { "max_running": 2, "running": 2 }`. Nothing is wrong with the instance: it stays (or returns to) `stopped`, or `sleeping` for a wake, with the refusal as `status_reason`, and the same request succeeds once another `mac` instance sleeps or stops.

### Templates
- `GET /v1/templates` -> system catalog first, then workspace templates by name.
- `GET /v1/templates/{name}` -> one template; `name@<revision>` for a pinned workspace revision; `404` if unknown or unpublished.
- `POST /v1/templates` body `RegisterTemplateRequest` (`name` lowercase `[a-z0-9-]{3,40}`, not starting with `warren-`; `image_ref` required) -> `201` template with `revision: 1`. The image is pulled and its digest recorded. Posting again with the same name publishes a new revision.
- `DELETE /v1/templates/{name}` -> `{ "name": "...", "deleted": true }`; `409 conflict` if instances use it.
- Starting an instance of a workspace template (`scope: workspace`) injects the daemon's static `warren-gateway` into the container at `/warren/warren-gateway` (`Config::INJECTED_GATEWAY_PATH`) and runs it as the entrypoint in wrap mode: it serves the Agent API, files, exec and health on port 3737 and supervises the image's own `ENTRYPOINT` and `CMD` as a child. The image's `USER` is kept. System templates ship the gateway and start as they are. On an injected gateway `GET /v1/health` adds `"wrapped": { "running": bool, "exit_code": int | null }`, the child's state (`running: false, exit_code: 0` for an image such as `alpine:3.20` whose `/bin/sh` exits at once; the instance stays `running`). The binary is fully static (musl), so this works for any Linux image, Alpine included; such images have no `ttyd`, so `<id>-7681` answers `502`. `default_port: 0` means the bare URL answers `502` while `<id>-3737.<base>` reaches the gateway. The daemon takes the binary from `--gateway-bin` (`WARREN_GATEWAY_BIN`), else next to `warrend`, else `/usr/local/bin/warren-gateway`; without one, instances of registered images that lack a gateway cannot start.

### Instances
- `POST /v1/instances` body `CreateInstanceRequest` (all optional; default template `warren-base`, `auto_sleep: false`, `idle_timeout_seconds: 900`, `network: "allow-all"`; `network` is `allow-all`, `deny-all` or `allowlist`, with `allowed_domains` and write-only `secrets` as described under [Egress allowlist and secrets](#egress-allowlist-and-secrets)). A missing `type` is taken from the template: `default` when the template allows it, else the template's first type, so `{"template": "warren-macos"}` alone creates a `mac` instance. Validation: template resolves; type allowed by template and a runtime exists for it (`performance` -> `not_supported`); shape per `warren_core::shapes::normalize` (on `mac` a requested disk below the base image's size is raised to it, the disk never shrinks); `idle_timeout_seconds` within `[MinIdleTimeoutSec, 86400]`; env keys `[A-Z_][A-Z0-9_]*`, at most 64 entries, values <= 4 KiB; metadata <= 32 entries; `allowed_domains` <= 64 valid patterns; `secrets` <= 16 valid entries, none of whose variables is also in `env`; `allowlist` or any secret on a daemon without a broker -> `not_supported`. Then the awake quota, when the daemon has one -> `409 instance_limit_reached`. Returns `201` with status `provisioning` immediately.
- `GET /v1/instances` -> list. `GET /v1/instances/{id}` -> instance. `PATCH /v1/instances/{id}` body `PatchInstanceRequest` -> instance (auto-sleep, idle timeout, name, metadata, env, network, allowed_domains, secrets; `metadata`, `env`, `allowed_domains` and `secrets` replace the whole set when present). Name, metadata, auto-sleep, idle timeout and `allowed_domains` change live; a `network` change recreates the runtime object (a running instance is stopped, recreated and started); `env` applies at the next recreate; see the section below for secrets.
- `DELETE /v1/instances/{id}` -> `{ "id": "...", "status": "deleting" }`; the instance is destroyed and removed.

### Egress allowlist and secrets

`network` has three values. `allow-all` is unrestricted egress (minus the host-wide blocks in [security.md](security.md)). `deny-all` has no route out. `allowlist` has no direct route out either: the instance's traffic goes to the daemon's **egress broker**, an HTTP forward proxy on the host (`--broker-listen`, default `0.0.0.0:7349`), which forwards plain `http://` requests and `CONNECT` tunnels (so HTTPS of any kind) only to hosts matching the instance's `allowed_domains`, and only to public addresses: a name that resolves to loopback, a private range, link-local (cloud metadata) or another reserved range is refused (`403 forbidden`), as is a destination given as a raw IP address. Non-HTTP protocols have no path out of an `allowlist` instance.

- `allowed_domains`: at most 64 entries, each a host name with at least two labels (`api.anthropic.com`) or a wildcard `*.suffix` (`*.npmjs.org` matches every name below `npmjs.org`, not `npmjs.org` itself). Lowercased and deduplicated; raw IP addresses, `localhost` and single labels are rejected. Stored and returned on the instance object in every mode (`allowed_domains` is omitted when empty), enforced in `allowlist` mode only.
- `secrets`: at most 16 entries `{ "name", "upstream", "header", "value", "env" }`, usable in every network mode. `name` and `env` are distinct variable names (`[A-Z_][A-Z0-9_]*`, not `WARREN_*` or a proxy variable, not also in `env`); `upstream` is an `https://` URL with an optional path prefix (no query, fragment or userinfo); `header` is the header the broker adds (`x-api-key`, `Authorization`, ... but not `Host`, `Content-Length` or another hop-by-hop header); `value` is the credential, 1..8192 bytes without control characters. **Write-only**: secrets never appear in any response (`GET`, list, create, patch), the instance object has no `secrets` field, and `Debug` output of the daemon redacts them. They are deleted with the instance. Stored in the daemon's database in plaintext, like `env`.
- What the instance receives, computed at every create, recreate and start: `WARREN_NETWORK` (the mode) and, when the daemon has a broker, `WARREN_BROKER` (`host:port` of the broker as reachable from inside, hidden from user commands like every `WARREN_*` variable except `WARREN_HOME`). In `allowlist` mode, and in `deny-all` mode when the instance has secrets, `HTTP_PROXY`, `HTTPS_PROXY`, `http_proxy` and `https_proxy` = `http://<broker>` and `NO_PROXY`/`no_proxy` = `localhost,127.0.0.1,<broker host>`, so curl, pip, npm, git and the provider SDKs go through the broker unchanged. Per secret: `<env>` = `http://<broker>/r/<token>`, a private route whose path is rewritten onto `upstream` with `header: value` added (`Authorization` gets `Bearer <value>` unless the value already carries a scheme), the response streamed back; and `<name>` = `warren-broker`, a placeholder so clients that insist on a non-empty key are satisfied. The token is random per instance and secret, and the broker honours it only from the address the instance was registered under; a secret that keeps its `name` across a `PATCH` keeps its token, so a new `value`, `upstream` or `header` applies to a running instance at once, while a new `name` or `env` becomes visible inside at the next recreate, like `env`.
- A daemon started with `--broker-listen none` has no broker: `allowlist` and `secrets` are refused with `not_supported`, and the instance receives `WARREN_NETWORK` only. `--broker-advertise HOST:PORT` overrides the address instances are told to use (derived per runtime otherwise: the Docker bridge gateway, `172.30.0.1` for Firecracker, `192.168.64.1` for `mac`).
- Errors from the broker, as seen by the program inside the instance: `403 forbidden` for an unknown source address, a mode that does not proxy, a host off the allowlist or a private destination; `404 not_found` for an unknown route token; `502 bad_gateway` when the destination cannot be resolved or reached; `504 timeout` when it does not answer. Bodies are `{ "error": { "code", "message" } }`.

Lifecycle operations below return `{ "id", "status" }`. In the single-node build they complete synchronously, so the status is the resulting state: `stop` answers `stopped`, `start` and `restart` answer `running`, `sleep` answers `sleeping`, `update` answers `running`; clients must still accept the transitional states (`stopping`, `starting`, `restarting`, `updating`) that a multi-node build may return.
- `POST /v1/instances/{id}/stop` -> `{ "id", "status": "stopping" }`. Stopped keeps the disk and never wakes on request.
- `POST /v1/instances/{id}/start` -> `{ "id", "status": "starting" }` (from stopped or sleeping). Enforces the awake quota.
- `POST /v1/instances/{id}/sleep` -> `{ "id", "status": "sleeping" }` now, regardless of auto-sleep. On `default` instances sleep stops the container and keeps the disk; any request to the instance URL wakes it (fresh boot, files intact), and the wake enforces the awake quota and the host capacity. On `mac` and `vm` instances sleep saves the memory next to the disk (Lume suspend; a Firecracker snapshot, so `disk_used_bytes` grows by the guest's RAM while asleep) and the wake resumes it with every process still running; a `vm` whose snapshot cannot be used boots cold instead. Memory checkpoints for `default` are a roadmap item.
- `POST /v1/instances/{id}/restart` -> `{ "id", "status": "restarting" }`.
- `POST /v1/instances/{id}/resize` body `{ "cpu"?, "memory"?, "disk"? }` -> `{ "id", "status", "resources" }`. Disk may only grow. The runtime applies live when it can, otherwise stop/apply/start.
- `POST /v1/instances/{id}/update` body `{ "template"?: "name" | "name@rev" }` -> `{ "id", "status": "updating", "image_ref", "template_revision" }`. Replaces the image, keeps `mount_path` data.
- `POST /v1/instances/{id}/fork` body `ForkRequest` -> `201` new instance (copy of disk, same template and env, new id and URL). Fork requires the source to be stopped or sleeping; a running source is slept first and woken after the copy. The new instance counts against the awake quota.
- `POST /v1/instances/{id}/exec` body `ExecRequest` -> `ExecResult`. Default user is the owner of the persistent home (the agent user in the built-in images); `"root"` is allowed. Wakes a sleeping instance; `409` if stopped. Output capped at 1 MiB per stream with `truncated: true`.
- `GET /v1/instances/{id}/logs?tail=200&since=<unix>` -> `{ "logs": "..." }`.
- `GET /v1/instances/{id}/screenshot` -> the screen of a `mac` instance as `image/png` (headers `X-Warren-Width`, `X-Warren-Height`); `?format=json` -> `{ "width", "height", "format": "png", "data": <base64> }`. Wakes a sleeping instance; `400 not_supported` on types without a screen (`default`, `vm`) and on a VM started with `--mac-vnc false`.
- `POST /v1/instances/{id}/input` body `{ "actions": [...] }` -> `204`. Actions, run in order: `{ "type": "click", "x", "y", "button": "left"|"right"|"middle", "count": 1..3 }`, `{ "type": "move", "x", "y" }`, `{ "type": "scroll", "x", "y", "dx", "dy" }` (wheel steps, positive is right and down, at most 50), `{ "type": "type", "text" }` (`\n` is Return, at most 1024 characters), `{ "type": "key", "key": "cmd+space" }` (modifiers `cmd`, `ctrl`, `alt`, `shift` joined with `+`; a character or `enter`, `escape`, `tab`, `space`, `backspace`, `delete`, `home`, `end`, `pageup`, `pagedown`, arrows, `f1`..`f24`). At most 100 actions per request; coordinates are screenshot pixels from the top left (the daemon scales them to the framebuffer, which on a Retina display is twice the screenshot). Same wake and `not_supported` rules as the screenshot.
- `GET /v1/instances/{id}/metrics?hours=1` -> `{ "data": [MetricPoint...] }` sampled every minute while running.
- `GET /v1/instances/{id}/signed-url?port=7681&ttl=3600&path=/` -> `{ "url": "http://ab12cd34ef-7681.<base>/?warren_token=...", "expires_at": ... }`. `port` omitted means the default port. TTL 60..86400.
- Backups: `GET /v1/instances/{id}/backups` list; `POST /v1/instances/{id}/backups` body `{ "note"? }` -> `201` backup (taken without stopping); `POST /v1/instances/{id}/restore` body `{ "backup_id" }` -> instance (stopped, restored, restarted if it was running).
- Crons: `POST /v1/instances/{id}/crons` body `{ "prompt", "schedule", "timezone"?, "name"?, "enabled"?: true }` -> `201` cron. `GET .../crons`, `GET .../crons/{cid}`, `PATCH .../crons/{cid}`, `DELETE .../crons/{cid}`. Only on agent templates (`agent_api: true`), else `not_supported`. Each firing wakes the instance and posts `{"input": prompt}` to the gateway's `/v1/responses` with no session id. `schedule` is a classic five-field expression: minute, hour, day-of-month, month, day-of-week, with day-of-week `0-7` where `0` and `7` are Sunday and names `SUN`..`SAT` accepted; shorthands such as `@daily` are rejected. The server translates it with `warren_core::cronexpr::to_cron_crate` before parsing.

## Agent API (served by the gateway inside the instance on port 3737)

Reachable at the instance URL after edge auth. The daemon reaches it directly by IP and authenticates with `x-warren-instance-token` on every route except health and version; the edge adds that header to proxied requests, so clients never see or send it. The token is the instance's `WARREN_INSTANCE_TOKEN`; the check is applied as middleware over the whole router before routing, so only the exact paths `GET /v1/health` and `GET /v1/version` answer without it and every other spelling or route (`//v1/files`, `/v1/./files`, `/`, unknown paths) needs it. A missing or wrong token -> `401 invalid_api_key` with a message naming the header. When `WARREN_INSTANCE_TOKEN` is empty (local runs) every route is open and the gateway logs a warning at startup.

Processes the gateway starts for users (`/v1/exec` children, the drivers' shells and commands, the `ttyd` terminal, the wrapped entrypoint) never inherit the `WARREN_*` platform variables except `WARREN_HOME`; the instance token in particular is not visible to agent commands.

- `GET /v1/health` -> `{ "healthy": true, "agent_ready": true, "driver": "openai", "version": "...", "home_owner": { "uid": n, "name": "agent" } }`. `home_owner` is the user agent commands run as and created files belong to (the owner of the persistent home under a root gateway, else the gateway's own user; a root-owned home under a root gateway is reported as uid 0 and logged loudly at startup). When the gateway was injected into a registered image and wraps its entrypoint, the object also carries `"wrapped": { "running": bool, "pid": n, "exit_code": n|null, "started_at": ms|null, "exited_at": ms|null }`.
- `GET /v1/version` -> `{ "version": "..." }`.
- `POST /v1/responses` body `{ "input": string, "session_id"?: string, "stream"?: bool, "model"?: string, "files"?: [string], "metadata"?: object }`.
  - Non-stream -> `{ "id", "session_id", "status": "completed" | "failed", "output_text", "created_at", "completed_at", "usage"?: {...}, "error"?: string }`.
  - Stream -> `text/event-stream` with named events: `response.created` `{id, session_id}`, `response.output_text.delta` `{delta}`, `response.tool_call` `{name, arguments}` (optional), `response.completed` `{id, session_id, output_text, status}`, `response.failed` `{id, error}`. Each event is `event: <name>\ndata: <json>\n\n`.
  - On a non-agent template -> `404 not_supported`.
- `GET /v1/responses/{id}` -> the response object. `GET /v1/responses/{id}/stream` -> replays stored events then follows a live one; ends with `response.completed`.
- `POST /v1/responses/{id}/cancel` -> `{ "id", "status": "cancelled" }`.
- `GET /v1/sessions` -> `{ "data": [{ "id", "name", "created_at", "updated_at", "message_count" }] }` newest first. `GET /v1/sessions/{id}` -> `{ "id", "name", "messages": [{ "role", "content", "at" }] }`. `PATCH /v1/sessions/{id}` body `{ "name" }`. `DELETE /v1/sessions/{id}`.
- `GET /v1/models` -> `{ "data": [{ "id": "default" }, ...] }`.
- Files, all paths relative to the persistent home and confined to it (`..` and absolute paths outside home -> `403 forbidden`): `GET /v1/files?path=.` -> `{ "path", "entries": [{ "name", "type": "file"|"dir", "size", "modified_at" }] }`; `GET /v1/files/content?path=` -> raw bytes with a content type guess; `PUT /v1/files/content?path=` raw body -> `{ "path", "size" }` (creates parents); `DELETE /v1/files?path=` -> `{ "path", "deleted": true }`; `POST /v1/files/move` body `{ "from", "to" }`; `GET /v1/files/download?path=` -> `application/gzip` tarball of a directory.
- `POST /v1/exec` body `ExecRequest` -> `ExecResult`. Used by the daemon for vm-type instances, for Docker instances while `--docker-checkpoints` is on (so the processes an exec leaves behind belong to the container's own process tree and survive a sleep), and by the cron scheduler; otherwise the docker runtime uses Docker exec. The child's environment is the gateway's minus the `WARREN_*` variables (except `WARREN_HOME`), plus `HOME`, `USER`/`LOGNAME` when switching user, and the request's `env`.
- `POST /v1/shutdown` -> `{ "status": "powering_off" }` in microVM init mode, else `400 not_supported`.
- `GET /v1/stats` -> `{ "at": unix seconds, "cpu_percent": 0..100, "memory_bytes", "memory_limit_bytes", "disk_bytes" }`: the guest's own view of its CPU, memory and the filesystem holding the home. Linux reads `/proc` and the cgroup limit; macOS reads `vm_stat`, `sysctl` and the 1-minute load (an approximation of CPU). The daemon uses it for `mac` instances, whose VMs it cannot measure from the host. Token required.

#### Interactive PTY (`GET /v1/pty`)
A WebSocket upgrade on the instance host (`ws(s)://<id>.<base>/v1/pty`, edge-authenticated like every instance route). The gateway starts `/bin/sh -l` on a pseudo-terminal as the home owner, with the same environment hiding as `/v1/exec`. Query parameters: `cmd` (a shell command run through `/bin/sh -lc` instead of a login shell), `cwd` (relative to the home), `cols` and `rows` (initial size, default 80x24), `term` (default `xterm-256color`). Binary frames carry terminal bytes both ways; a text frame `{"type":"resize","cols":N,"rows":N}` resizes; when the process exits the gateway sends `{"type":"exit","code":N}` and closes. Closing the socket hangs up and then kills the process group. The CLI's `warren shell` and `warren run` use it (see [run.md](run.md)).


Agent drivers (selected by `WARREN_AGENT_DRIVER`):
- `echo`: deterministic for tests. Replies `echo: <input>`; an input starting with `!` runs the rest as a shell command and replies with its combined output; `!!sleep N` style commands are allowed. Streams the reply in at least two deltas.
- `openai`: an agent loop against an OpenAI-compatible chat-completions endpoint (`OPENAI_BASE_URL`, `OPENAI_API_KEY`, model from `WARREN_MODEL`) with tools `run_shell(command)`, `read_file(path)`, `write_file(path, content)`, `list_dir(path)`; at most 12 tool iterations per turn; session history is the message list; streams the final answer.
- `command`: runs `WARREN_AGENT_COMMAND` once per turn with the prompt as the last argument (`{prompt}` placeholder supported) in the home directory; stdout is the reply.

Sessions and responses persist as JSON files under `<home>/.warren/`.

## Edge rules

1. Parse Host with `Config::parse_host`. `root` -> dashboard, except paths under `/v1/` which go to the API. `api` -> API.
2. `instance`: resolve auth: `X-Warren-Key` or `Authorization: Bearer` -> `Authenticator`; else `?warren_token=` -> `Signer.Verify` (id and port must match the host; port 0 in the token means the default port) -> set cookie `warren_session=<token>` (HttpOnly, SameSite=Lax, Path=/, Secure on https) and `302` to the same URL without the token. The `Location` is absolute (`<scheme>://<request Host><path>[?rest]`); a path starting with `//` is refused with `400 invalid_request`. Else cookie `warren_session` -> verify likewise, and the request must be same-origin: `Origin` and `Referer`, when present, must be the instance's own origin (`instance_url(id)`, `preview_url(id, port)` on a port host, or `<scheme>://<request Host>`), and `Sec-Fetch-Site`, when present, must be `same-origin` or `none`. A top-level document navigation with GET/HEAD (`Sec-Fetch-Mode: navigate`, `Sec-Fetch-Dest: document`) is accepted regardless, which is how a signed URL opened from the dashboard becomes a cookie request after the 302. A cookie on a cross-origin request -> `401 invalid_api_key` and nothing is proxied. Other failures -> `401 invalid_api_key` JSON.
3. The instance must belong to the authenticated workspace (key auth) -> else `404 not_found`.
4. `Lifecycle.EnsureAwake(id)` (which enforces the awake quota when the instance is asleep); `Lifecycle.RecordActivity(id)` on every proxied request and response.
5. Proxy to `http://<ip>:<port>` with `httputil.ReverseProxy`, preserving path and query, setting `X-Forwarded-Host`, `X-Forwarded-Proto`, `X-Forwarded-For`, stripping `X-Warren-Key` and any client-sent `X-Warren-Instance-Token`; `Authorization` is forwarded only when it is not a Warren key (a `Bearer sk_live_...` is the edge's credential and is removed whether or not it authenticated; any other value is the instance's own and passes through); the `warren_session` cookie is stripped from the forwarded Cookie header. The edge resolves `Lifecycle.GatewayCredentials(id)` and, when the instance token is non-empty, sets `X-Warren-Instance-Token` on the upstream request. WebSocket upgrades pass through. Proxied requests stream and have no overall deadline; Sandbox API requests have a 60 s deadline (`504 timeout`) except `POST /v1/instances/{id}/exec`, which runs to its own `timeout_sec`. The listener caps requests in flight (4096); further requests queue.
6. Port: 0 -> `Instance.DefaultPort`; if the default port is 0 -> `502` with text "this template has no default port".
